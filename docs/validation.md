## 资源测量

脚本：`scripts/measure-process.ps1`，聚合根进程及子进程的私有内存、工作集和 CPU 时间。下面为同机、同一份两任务数据的短时样本；原版使用冻结 `1d51ac9` 的生产前端及 Electron 45.1.0 独立 profile。Rust 界面还包括单独交接的导航增量。原版 MCP 后台沿基线启动，Rust 样本 MCP 已开启。记录全部来自真实进程树，不包含编译器内存。

| 状态 | 进程数 | 私有内存 MiB | 原始记录 |
| --- | ---: | ---: | --- |
| 原版主界面空闲 | 4 | 227.45 | `legacy-main-idle.json` |
| 原版关闭主界面超过30秒 | 4 | 220.47 | `legacy-closed.json` |
| Rust 首次原生后台 | 1 | 39.32 | `rust-native.json` |
| Rust 主界面展开 | 7 | 227.22 | `rust-main.json` |
| Rust 主界面释放后，专注继续 | 1 | 42.95 | `rust-released.json` |

路径均位于 `reports/resources-20261030/`。这些3–5秒采样中 CPU 时间没有可见增长，不能据此声称持续0% CPU。结果支持“收起后释放 WebView 降低常驻开销”；完整界面展开时，本次私有内存接近。样本很小，且同机有其他程序和编译负载，不能推广为稳定性能保证。

另用四任务验收数据测得：仅快速输入展开时7进程、228.65MiB（`rust-quick.json`）；随后收起输入，回到1进程、44.27MiB（`rust-after-quick-release.json`）。完整 WebView2 运行时是输入态的主要基础成本，必须收起释放才能取得常驻收益。该组数据与上表两任务样本不同，单独列出。

日志中已有主界面时打开输入，从请求至前端完成快照加载并发 `ready` 为0.385秒；全新启动打开主界面的一次样本为4.711秒。并行编译期间另测得10.889秒，受负载影响明显，不计作空闲启动指标。这些均为单次应用内部就绪时间，非屏幕首帧或稳定分位数；后续应在固定空闲条件下复测和优化。
