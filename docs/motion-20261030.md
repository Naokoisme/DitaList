# 悬浮栏与主窗口动效修正

用户明确要求两段都参考 iOS 打开 App 的连续展开：白色细线与悬浮栏之间，以及点击栏后打开主窗口。原 `9e0220d` 的 180ms 动画只改变父窗口边界，按钮仍按完整尺寸绘制，产生裁切感。本次替换这段实现，产品布局、业务数据和版本号保持。

## 交互与实现

- **细线与栏：** 临界阻尼弹簧驱动容器、圆角、背景和整组内容。文字与图标等比缩放、同步显现；中途反向承接位置和速度。固定贴边一侧，只向工作区内展开；暗色主题也从白色细线连续变化。
- **原生绘制：** 转场期间临时使用预乘 alpha 的 32bpp DIB、Direct2D 和 `UpdateLayeredWindow`；同一帧提交位置、形状及内容。按钮暂时隐藏，动画期间的点击按视觉位置识别，展开后只执行一次。结束或取消恢复标准原生按钮，释放画布与计时器。动画期间不创建 WebView。
- **主窗口：** 真实 App 从栏所在的屏幕位置整体展开，约 520ms。透明主 WebView 临时覆盖起止区域，App 维持目标布局尺寸；内容等比缩放，容器、圆角、背景连续变化。原生主窗只在开始和结束改变尺寸，完成后恢复通常的窗口范围。
- **交接：** 冷启动等待界面期间保持栏展开，准备完成后接替；重复点击不重开动画。关闭、失败、超时及退出都撤销交接并恢复入口；减少动画时直接显示。恢复贴边栏后，鼠标已离开也重新安排自动收起。
- **显示器与最大化：** 非最大化的隐藏主窗可跟随栏所在屏幕，避免跨 DPI 中途改变字体尺寸；跨屏且已经最大化的主窗保持原位置普通显示。已经可见或最小化的主窗正常聚焦／还原，不重复播放展开动画。最大化结束使用直角，还原恢复圆角。
- **线程：** 窗口操作与超时收尾串行，托盘和单实例的 UI 回调只派发工作，避免 UI 线程和窗口操作锁互等。

沿用已有 Windows 绑定；`windows-numerics 0.3.1` 已在锁文件中，本次将其列为直接依赖以使用 Direct2D 的坐标类型，没有新增渲染框架。字体方案由独立设计讨论处理，本次保持已有字体。

参考的是连续运动与速度衔接原则，参数按本产品调节，不声称复刻系统私有实现：[Apple 的弹簧动画说明](https://developer.apple.com/videos/play/wwdc2023/10158/)、[Windows 分层窗口 API](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-updatelayeredwindow)。
