# 2026-11-01 桌面交互反馈修正

本轮按三项试用反馈调整源码，产品版本保持 `0.0.0`。候选生成及桌面快捷方式更新的实际结果记录在本地 `reports/feedback-20261101/verification.json`，以源码提交和 SHA-256 区分候选，不推送或发布。

## 问题与处理

| 反馈 | 已确认的代码原因 | 源码修复 |
| --- | --- | --- |
| 水流缩放观感异常 | 主窗先扩为覆盖悬浮栏与目标窗的透明画布，再以 820ms 曲线路径和内容缩放展开；最小化恢复也进入同一路径 | 移除主窗曲线、临时画布、DWM 禁用过渡、裁剪和分阶段握手。冷开、隐藏缓存与最小化恢复统一使用 Windows 显示／还原和聚焦 |
| 只能从六点拖柄拖动 | 普通按钮仅 `id == DRAG` 才检测拖动；父栏空白静止时跳过手势；动画表面也仅拖柄可跨阈值移动 | 原生栏所有按钮与空白共用父栏捕获。跨系统阈值后进入系统移动，短释放才执行按钮操作。拖动、越界、取消和捕获丢失均撤销点击 |
| 主界面显示后需要等待才能点击 | 转场设置 `surface.inert = true`，保持到结束握手；异常依赖三秒超时。外壳就绪可早于业务快照及订阅就绪 | 移除转场禁交互和超时链路，业务界面 `ready(main)` 后直接显示。冷启动仍需创建 WebView2，显示后不再等待自定义动画 |

原生栏贴边细线、悬停收展及快速输入的文本编辑保持原有规则。输入态 Web 文本区域保留文本选择；本轮“任意位置拖动”覆盖原生栏的六点、今天、待确认、提醒、＋和空白。

窗口仍在关闭后缓存 30 秒。取消开窗、最小化和超时销毁会释放原生栏保护态；超时销毁与 ready 使用同一窗口交接锁，迟到 ready 不重新拉起已经关闭或最小化的主窗。`runtime.jsonl` 的 `main_window` 事件记录 requested、ready、shown 及耗时。

真实鼠标验收还复现了一个边界：取消按压后，在 500ms 系统双击时限内再次点击，原生按钮收到 `WM_LBUTTONDBLCLK`，原处理只接收普通按下，导致第二次短按失效。现将两种消息接入同一条按压路径，修复后相同操作连续三次成功。[微软按钮消息说明](https://github.com/MicrosoftDocs/win32/blob/docs/desktop-src/Controls/button-messages.md)确认了自绘按钮的双击消息差异。
