# 2026-11-01 快速输入外观修正

本轮依据试用截图移除六点拖柄，将＋展开改为同一条紧凑输入栏。产品版本保持 `0.0.0`，本地候选用源码提交和 SHA-256 区分，不推送或发布。

## 原因与实现

旧版输入表面距离窗口原点各 10 DIP，窗口尺寸另加 20 DIP；Web 表面自身还有边线和阴影。宿主使用不透明、带默认阴影的无装饰窗口，透明留白因此露出窗口背景，形成截图中的第二层框。Tauri 对 Windows 无装饰窗口的阴影还注明了额外白边行为，见 [WindowBuilder 文档](https://docs.rs/tauri/latest/tauri/window/struct.WindowBuilder.html#method.shadow)。

- 原生栏和输入条均移除六点按钮。最短原生栏为 140×40 DIP，今天入口 100 DIP，＋入口 40 DIP。
- 点击＋后由单个按需创建的透明 Web 窗口接替原生栏。输入表面从窗口原点开始，无外围留白，关闭系统阴影，只保留一圈 1 DIP 边线和 8 DIP 圆角。
- 单行输入总高 40 DIP，初始宽度 420 DIP；有额外数量入口时增加相应宽度，最大 560 DIP。输入较长时换行，多行和错误提示按实际表面高度调整窗口。
- 有空间时固定左边缘向右延伸，右侧空间不足时固定右边缘向左展开。宿主统一限制窗口处于当前显示器工作区内。
- 非文本区域保留拖动，短按执行入口操作；输入框内保留选字和编辑。回车提交、Esc／收起保留草稿，中文输入法组合与失败重试沿用现有核心协议。

实机还复现了输入态拖动的交接问题：输入窗已关闭、左键仍按下，恢复后的原生栏没有进入系统移动循环。仅补前台激活仍失败。最终在窗口交接后重新建立原生鼠标捕获，复用普通栏的阈值与取消路径；同一手势的栏位置由 `(1317,761)` 移到 `(1445,693)`，草稿保留且未误开主界面。微软对[鼠标捕获](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setcapture)说明了前台与线程归属要求；实际修复结果由真实鼠标记录确认。
